# ThermoPlan 디자인 시스템 (v5: 밝은 면, 파란 강조, 메뉴 두 개)

IT관 냉난방을 운영하는 시설 담당자의 도구이자, 심사장 프로젝터(1440–1920px)에 띄우는 시연 화면이다.
v5는 팀 시안(흰 카드, 파란 강조색, 메뉴 2개, 등각 평면도, 강의실 집중 화면)을 따른다. v4의 "화면당 질문 하나, 누르면 자세히" 원칙과 데이터 색은 그대로 둔다.

## 1. 원칙

1. **메뉴는 두 개.** 사이드바에는 `운전 현황`과 `스케줄 타임라인`만 둔다. 나머지 화면은 지우지 않고 두 메뉴 안의 탭으로 옮긴다(아래 3절). 경로(`/energy`, `/plan` …)는 그대로라 링크와 북마크가 깨지지 않는다.
2. **화면당 질문 하나.** 첫 화면에는 답 한 문장 + 핵심 수치 최대 3개 + 주 시각물 하나만 둔다. 보조 분석은 펼침 목록·팝오버·서랍으로 옮긴다(v4 그대로).
3. **밝은 면, 파란 강조.** 크롬은 거의 흰 바탕·흰 카드·헤어라인·남색 글로 만들고, 상호작용(주 버튼, 선택된 메뉴·탭·칩, 재생 막대, 선택된 강의실)은 브랜드 파랑 하나로 표시한다. 전략·온도·운전 모드·상태 색은 데이터 안에서만 쓴다.
4. **건물은 평면으로, 강의실은 크게.** 운전 현황의 주 시각물은 층별 등각 평면이다. 강의실을 누르면 같은 자리에서 그 강의실 화면(큰 호수, 강의실 모양, 예상 재실 인원, 상태, 온도·전력 차트)으로 바뀐다.
5. **수치는 크고 또렷하게.** 큰 수치는 `tabular-nums`, 단위는 작고 흐리게.
6. **움직임은 응답일 때만.** 펼침·서랍·팝오버는 150–250ms로 투명도와 위치만 바꾼다. 상시 움직임은 정상 상태 알약의 점(은은한 파동), 재생 중인 시간 막대, 실외기를 펼쳤을 때의 팬 회전뿐이다. `prefers-reduced-motion`이면 모두 끈다.
7. **깨지지 않는다.** 응답 모양 검사, 화면·패널별 ErrorBoundary, 화면별 코드 분할, 키보드·포커스 링은 v3·v4 그대로.

## 4. 운전 현황(현황 탭)

| 상태 | 첫 화면 | 한 번 눌러야 보이는 것 |
|---|---|---|
| 건물 전체 | 제목 "운영 현황" + 데이터로 만든 답 한 문장 + 수치 3개(지금까지 AI 전력, 고정 대비, 강의 중 쾌적) · **층별 등각 평면**(4F·3F 판 위 뒷줄에 강의실 타일: 호수·온도·모드 아이콘·수업 중 표시, 앞줄에 EV·계단·화장실 같은 다른 공간을 낮고 흐리게) + 시간 막대 + 범례 한 줄 | 강의실 타일 → 강의실 화면 · 수치 → 근거 팝오버 · "실외기" 칩 → 뒷줄 뒤 배관과 실외기 칩 · "다른 시점" → 재현 시각 · 펼침 목록: 오늘 운전 타임라인, AI 판단과 자동 조치, 외기와 예보 |
| 강의실 화면(`?room=407`) | "건물 전체" 버튼 + 강의실 칩 줄(가동 중이면 모드 색 점) · 왼쪽 큰 카드: **"4F - 407"**, 유형·정원, 평면도와 같은 기울기의 강의실 판(정원만큼 좌석, 예상 인원만큼 채움, 뒷벽에 실내기), "예상 재실 인원 약 40명" · 오른쪽: 상태 카드(HVAC 상태 배지 "난방 중 2.0 kW", 목표 온도, 실내 온도, 진행 중/다음 수업, 실외기) + **"실내온도와 전력"** 차트(위 온도, 아래 전력, x축 공유. 전략 칩 고정·수동·규칙·AI(적용 중), 기본은 고정과 AI) | 하루 요약 수치 4개와 현재 운영 대비 문장 · 펼침 목록: 강의별 검증 결과, AI 판단 근거, 설비 켜고 끈 기록, 설비 정보 · 운전 계획 CSV |

- 타임라인·정합성 검증 화면은 같은 강의실 화면을 서랍(940px)으로 연다(`RoomDrawer`). 서랍에서는 "그날" 기준으로 상태 카드가 바뀐다(그날 AI 가동 시간, 첫 수업).
- 시안의 이중 y축 차트(왼쪽 ℃, 오른쪽 kW)는 쓰지 않고 위아래 두 칸으로 나눴다(차트 규칙: 이중 y축 금지).
- 시안의 층 표시가 바뀌어 있어(3F 판에 4xx 호실) 실제 층(4F: 405–410, 3F: 306·307·309·310)으로 그렸다. 데이터가 있는 강의실은 이 10개뿐이고, 다른 공간 타일은 위치를 읽기 위한 장식이다(누를 수 없음, 스크린 리더에서 숨김).

## 5. 차트 규칙 (dataviz, v3 유지)

- 선 2px, 막대 ≤ 24px·끝 4px 둥글게·바닥 각짐, 점 ≥ 8px + 2px 바탕 테두리. 격자·축은 실선 헤어라인, 축 눈금 12px `ink-3`.
- 이중 y축 금지(외기온도는 x축을 공유하는 아래 칸). 2개 이상 계열이면 범례, 4개 이하면 직접 라벨도. 글자는 잉크 색.
- 주요 차트는 `표` 보기 유지. 툴팁은 값이 먼저.
- 폭포: 합계는 전략 색, 규칙 단계 파랑, AI 기능 청록, 전력이 늘어난 단계는 청록 테두리 + 옅은 면("쾌적을 위한 전력").
- 기본 화면의 차트에는 주 시각물을 읽는 데 필요한 범례만 둔다. 예: 단면도는 "온도 색 + 모드 아이콘" 한 줄, 간트는 보이는 층만.

## 6. 글쓰기

- 합니다체 설명, 명사형 라벨, 동사형 버튼("미리보기 실행", "등록하고 다시 계산"). 같은 동작은 끝까지 같은 이름.
- 오류는 무엇이, 왜, 어떻게 하면 되는지. 빈 상태는 다음 행동을 안내.
- 요약 문장은 데이터로 계산한다(LLM 호출 없음). 수치를 지어내지 않는다. 미래 시각은 "예정/예상"을 밝힌다.
- `cold_starts`는 춥거나 더운 시작을 모두 세므로 "시작 시 쾌적 이탈"(좁으면 "시작 이탈").

## 7. 계획 검토 (v4 기록, v5에서 바뀐 점은 1–4절)

1. **카드 키트 회피**: 처음엔 핵심 수치 3개를 같은 카드 3장으로 그리려 했다. 생성 디자인의 대표 특징(같은 카드 나열)이라 카드 없이 제목 옆 수치 줄로 바꿨다.
2. **강조 색**: 애플식 파랑 하나를 상호작용 색으로 쓰려 했으나 규칙 기반 파랑(`#2a78d6`)·냉방 파랑과 겹친다. 잉크 남색을 유일한 상호작용 색으로 두고 포커스 링만 파랑으로 남겼다.
3. **그림자 vs 헤어라인**: 둘 중 하나만 고르라는 브리프에 따라, 프로젝터에서 살아남는 헤어라인을 골랐다. 카드에 그림자를 주지 않는다.
4. **제도 격자 바탕**: 단면도 뒤 격자 무늬는 '조용함'을 해친다. 무늬를 없애고 흰 면 위에 슬래브만 남겼다.
5. **펼침 vs 탭**: 절감 효과의 보조 분석 6개를 탭으로 두면 첫 탭 내용이 스크롤하면 늘 보인다. "누르면 보인다"는 요청에 맞춰 펼침 목록으로 했고, 펼칠 때 처음 그려 첫 화면도 가벼워진다.
6. **AI 요약 문장**: "오늘 AI가 n% 아꼈습니다"는 옆 수치와 겹친다. 문장은 '지금 상태와 다음 조치'를, 수치는 '오늘 누적'을 맡겨 겹치지 않게 했다.
7. **글자 크기**: v3의 11–12.5px 글을 13px 이상으로 올렸다(차트 축 눈금 12px만 예외). 프로젝터 가독성.
8. **장식 제거 목록**: 단면도의 강의실 유형·강의명·전력 글자, 실외기 칩(토글 뒤로), 온도 분포 점그림(범례 한 줄로 대체), 타임라인의 kWh·유형 라벨, 검증 방법 3단 설명, 달력 칸의 "강의 n"·조치 아이콘, 요약 띠의 보조 문장.

## 8. 성능과 견고함

- 화면별 `React.lazy`, ECharts는 차트가 있는 화면·펼침에서만, 코파일럿은 처음 열 때 불러온다. 펼침 목록의 차트·요청은 펼칠 때 시작한다.
- 응답 모양을 확인한 뒤 쓰고(빠진 목록은 빈 목록, 필요한 수치가 없으면 그 부분만 오류), 화면(경로마다)·코파일럿·앱 전체에 ErrorBoundary.
- 다시 계산 중인 응답(`stale`)은 이전 값을 흐리게 유지하고 "갱신 중"을 작게 표시, 10초 뒤 다시 확인.
- `/api/attribution`은 계산 중이면 202 → 10초마다 확인.

## 9. 구현 후 검토 (Vercel Web Interface Guidelines)

바꾼 파일 전체를 가이드라인 목록으로 점검하고 고친 것:

- 모든 `<button>`에 `type`, 아이콘만 있는 버튼에 `aria-label`, 장식 아이콘에 `aria-hidden`. 펼침·팝오버 버튼에 `aria-expanded`/`aria-controls`.
- 입력에 `name`·`autoComplete`·`inputMode`, 자리 표시 글은 "…"로 끝냄. 이미지에 `width`/`height`.
- `transition: all` 없음, 레이아웃 속성 애니메이션 제거(코파일럿 열 때 본문 여백, 토글 스위치는 `transform`). 서랍·모달·코파일럿 목록에 `overscroll-behavior: contain`.
- 시간 막대를 끌 때마다 읽히던 요약 문장의 `aria-live` 제거(스크린 리더 소음). 토스트·일정 확인은 `aria-live="polite"` 유지.
- 서랍·모달 제목을 `h2`로(페이지 `h1` 아래 위계 유지). 상단 막대가 포커스된 요소를 가리지 않게 `scroll-padding-top`.
- 화면 상태를 URL에: 절감 효과 범위(`?scope=all`), 간트 표시 층(`?plan=1`, `?dec=1`), 일정·데이터 탭(`?tab=`), 날짜·강의실(`?date=`, `?room=`).
- `color-scheme: light`, `<meta name="theme-color">`, 상호작용 요소에 `touch-action: manipulation`.
- 날짜 표기 `fmtDateK`를 `Intl.DateTimeFormat('ko-KR')`로 바꿈(출력은 같음). 시각(`10:40`)·짧은 날짜(`11/20`)는 표·축 정렬을 위해 고정 형식 유지.
- 남긴 예외: 오버레이 배경 클릭으로 닫기(키보드는 Esc), 간트 막대의 마우스 툴팁(같은 정보는 강의실 서랍에 있음), 강의 목록 129행은 가상화하지 않음(50행 기준을 넘지만 스크롤 틀 안이고 렌더 비용이 작음).
