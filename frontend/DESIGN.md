# ThermoPlan 디자인 시스템

IT관 냉난방을 운영하는 시설 담당자의 도구이자, 심사장에서는 1280–1920px 프로젝터 화면에 띄우는 시연 화면이다.
담당자는 "지금 어느 방이 왜 켜져 있는가, 얼마나 아꼈는가"를 몇 초 안에 읽어야 한다.

## 1. 콘셉트: 제도 도면 위의 열 지도

- **바탕은 건축 도면**: 차가운 제도 용지색 바탕(paper)에 남색 제도 잉크(ink)로 선과 글을 쓴다. 크롬(내비게이션·버튼·패널)은 무채색에 가깝게 두고 색을 쓰지 않는다.
- **색은 데이터에만 쓴다**: 온도(차가움↔따뜻함), 운전 모드(난방·냉방·송풍), 전략(고정·수동·규칙·AI), 상태(정상·자동 조치·확인 필요). 이 네 가지 외의 장식 색은 없다.
- **대담한 요소는 한 곳에만**: 운영 현황의 *IT관 분해 단면도(2.5D)*. 3층과 4층 슬래브를 띄워 겹쳐 그리고, 방의 바닥을 실내온도 색으로 칠한다. 아래의 시간 막대를 끌면 하루 동안 건물이 데워지고 식는 모습이 재생된다. 나머지 화면은 조용하고 촘촘하게 둔다.

## 4. 간격·모서리·높이

- 간격 4px 단위: 4·8·12·16·20·24·32. 패널 사이 16, 패널 안쪽 20(조밀한 패널 16), 페이지 제목과 본문 사이 20.
- **모서리는 위계를 따른다**: 패널 10px > 패널 안 타일·표 틀 6px = 컨트롤(버튼·입력) 6px > 배지 4px. 데이터 막대 끝 4px(바닥 쪽은 각짐).
- **그림자는 '떠 있는 것'에만**: 패널은 헤어라인 테두리만, 그림자 없음. 툴팁·토스트 = 떠 있음(`0 8px 24px rgb(20 32 51/.12)`), 서랍·모달·코파일럿 = 위에 덮음(`0 16px 48px rgb(20 32 51/.18)`, 배경 `rgb(20 32 51/.32)`).
- 강조 패널은 그림자 대신 면으로 구분: 히어로 단면도 패널만 제도 격자(24px) 바탕을 쓴다.

## 5. 레이아웃

```
┌ 사이드바 216 ┬ 상태 막대: 위치 · 실시간 시계 · 외기 ··············· [AI 코파일럿] ┐
│ 로고(슬래브 2장) │ 페이지 제목 22 + 한 줄 설명                     [범위·동작]  │
│ 내비 6         │ ┌ 패널 ─────────────────────────────────────────────────┐ │
│               │ │ …                                                       │ │
│ 건물·학기 정보  │ └─────────────────────────────────────────────────────────┘ │
└───────────────┴──────────────────────────────────────────────────────────────┘
```
- 왼쪽 정렬. 본문 최대 1600px. 1024px 미만은 사이드바가 상단 가로 탭이 된다. 1536px 이상에서 코파일럿을 열면 본문 옆에 붙는다.
- 같은 모양 카드 여러 개를 나란히 놓지 않는다. 지표 묶음은 **한 패널을 헤어라인으로 나눈 지표 띠(StatStrip)**, 전략 비교는 **전략이 열인 비교 표**로 만든다.

## 6. 차트 규칙(dataviz 스킬 준수)

- 선 2px, 막대 두께 ≤ 24px·끝 4px 둥글게·바닥 각짐, 쌓은 막대 사이 2px 바탕색 간격, 점 ≥ 8px + 2px 바탕색 테두리.
- 격자·축은 실선 헤어라인(`#e6eaef`/`#c9d1db`), 축 글 11px `ink-3`. 이중 y축 금지(외기온도는 x축을 공유하는 아래 칸).
- 2개 이상 계열이면 범례 항상, 4개 이하면 직접 라벨도. 글자는 계열 색이 아닌 잉크 색.
- 툴팁: 값이 먼저·굵게, 계열 이름은 짧은 선 키와 함께. 모든 주요 차트에 `표` 보기.
- 다시 불러올 때는 이전 그림을 흐리게 유지(스켈레톤 깜빡임 없음). 첫 로딩만 스켈레톤.

## 7. 컴포넌트 규칙

- **Panel**: surface + 1px line + 10px. 머리(제목 15 + 설명 12 `ink-3`, 오른쪽 동작)와 본문.
- **StatStrip**: 한 패널 안의 지표 칸. 라벨 12 `ink-2` → 값 26 → 보조 12. 칸 사이 세로 헤어라인.
- **Button**: 주(남색 바탕·흰 글), 보조(흰 바탕·`line-strong`), 고스트, 위험. 높이 32(sm 28). 버튼 글 뒤에 화살표를 붙이지 않는다.
- **Badge**: 4px, 11.5px/500, 옅은 바탕 + 진한 글. 상태 배지는 아이콘 필수.
- **Segmented/Tabs**: 선택 = 흰 면 + 헤어라인(세그먼트), 2px 남색 밑줄(탭).
- **입력**: 높이 34, 6px, 포커스 시 `focus` 링.
- **포커스**: 모든 상호작용 요소에 `:focus-visible` 2px 링. 평면도의 방도 Tab으로 이동하고 Enter로 연다.
- **움직임**: 사용자 동작에 대한 반응(서랍 열림, 항목 펼침)만. 상시 움직임은 가동 중 실외기 팬 회전 하나. `prefers-reduced-motion`이면 모두 끈다.

## 8. 글쓰기 규칙

- 합니다체 설명, 명사형 라벨, 동사형 버튼("미리보기 실행", "등록하고 다시 계산"). 같은 동작은 끝까지 같은 이름(버튼 "저장" → 토스트 "저장했습니다").
- 오류는 사과하지 않고 무엇이 왜 실패했고 무엇을 하면 되는지 쓴다. 예: "서버에 연결하지 못했습니다. 백엔드가 실행 중인지 확인한 뒤 다시 시도하세요."
- 빈 상태는 다음 행동을 안내한다. 예: "등록된 이벤트가 없습니다. 위 입력창에 일정을 적어 보세요."
- 패널 제목 위의 눈썹 라벨, 'A · B · C'로 이어 붙인 메타 문자열, 'WORD — 조각' 형식은 쓰지 않는다. 메타 정보는 간격으로 나눈 항목(Meta 컴포넌트)으로 보여 준다.

## 9. 계획 검토(만들기 전에 브리프·흔한 생성 디자인 특징과 대조해 바꾼 것)

1. **바탕색**: 처음엔 기존의 따뜻한 미색(`#f6f6f3`)을 유지하려 했으나, 생성 디자인의 대표 특징(크림 바탕)에 가깝고 냉난방이라는 주제와도 맞지 않았다. 차가운 제도 용지색으로 바꿨다.
2. **브랜드 색**: 청록 브랜드 버튼은 AI 전략 색과 겹쳐 '색 = 데이터' 원칙을 흐린다. 크롬은 남색 잉크로 통일하고 색은 데이터에만 남겼다.
3. **사이드바**: 진한 남색 사이드바를 검토했지만 관리자 템플릿의 기본값이다. 바탕과 같은 면 위의 조용한 목록으로 두었다.
4. **평면도 투영**: 정식 30° 등각 투영은 긴 건물(방 7칸)에서 높이가 1000px을 넘어 한 화면에 들어오지 않는다. 앞면이 왜곡되지 않는 낮은 사선 투영(평면을 뒤로 눕히고 높이를 세움)으로 바꿔 두 층이 360px 안에 들어오게 했다.
5. **KPI 카드 다섯 개**: 똑같은 카드 나열(SaaS 카드 키트)을 한 패널의 지표 띠로 바꿨다. 절감 효과의 전략 카드 4장은 전략이 열인 비교 표로 바꿨다.
6. **메타 문자열**: '·'로 이은 부제 대신 항목 간격으로 나눈다. 화살표가 붙은 버튼 글('전체 보기 →')을 없앴다.
7. **온도 색**: 쾌적 범위 안을 초록으로 칠하려 했으나 AI 전략 색·정상 상태 색과 충돌한다. 발산형 규칙대로 중간값을 무채색으로 두었다.

## 10. 성능

- 화면별 `React.lazy` 분할, 코파일럿(마크다운 렌더러 포함)은 처음 열 때 불러온다. ECharts는 차트가 있는 화면에서만 불러오는 별도 청크.

## 11. 공정한 비교 (v3에서 추가)

심사에서 나올 질문 세 가지를 화면이 먼저 답한다: 고정 스케줄은 허수아비 기준인가, 왜 단순 규칙이 아니라 AI인가, 절감은 어디서 오는가.

- **대표 수치는 같은 쾌적도 비교**: 절감 효과 화면의 히어로는 "같은 쾌적도라면: 규칙 기반(30분 전 가동) vs AI 예측 제어"의 차이다. 쾌적 유지율·시작 시 쾌적 이탈·불쾌 누적을 같은 표에 나란히 두고, 규칙이 나은 항목도 굵게 표시한다(감추지 않는다). 고정 스케줄 대비 수치는 오른쪽 보조 칸으로 내렸다.
- **폭포 차트(기능별 절감)**: 고정 스케줄 → 수업 시간에만 운전(규칙) → 예측 기동·관성 정지 → 날씨 판단 → 재실 감지 = AI.
  - 색은 "누가 줄였나"를 따른다: 합계 막대는 전략 색(고정 회색, AI 청록), 규칙 단계는 규칙 파랑, AI 기능 단계는 AI 청록. **전력이 늘어난 단계는 청록 테두리 + 옅은 면**으로 그리고 위에 "+97.5 / 쾌적을 위한 전력"을 적는다(숨기지 않고 비용으로 설명).
  - 막대 24px, 단계 사이는 누적값 높이의 헤어라인 연결선, 막대 위 숫자는 앞 단계 대비 변화량.
  - 막대 아래에 단계별 **시작 시 쾌적 이탈(회)**과 쾌적 유지율을 표처럼 정렬한다. 큰 변화(±5회 이상)는 초록/빨강 변화량을 붙인다.
  - 재실 감지 단계에는 각주 번호를 달고, API `note`의 센서 가정(PIR·CO₂ 또는 출결 연동)을 차트 아래에 적는다.
- **용어**: API `cold_starts`는 너무 춥거나 더운 상태(쾌적 범위 ±0.3℃ 밖)에서 시작한 강의 수이므로 "저온"이 아니라 **시작 시 쾌적 이탈**(좁은 곳은 "시작 이탈")로 부른다. 정의는 `constants.ts`의 `COLD_START` 한 곳에 둔다.
- **전력 vs 쾌적 산점도**: 규칙 변형(10분 전·30분 전·재실 감지)은 같은 규칙 파랑에 모양(원·마름모·삼각형)과 직접 라벨로 구분한다(산점도의 색 상한 3개 유지: 회색·파랑·청록).

## 12. 시스템 상태와 일정 확인 (v3에서 추가)

- **상단 상태 표시**: 오른쪽, 코파일럿 버튼 앞. 정상은 초록 점 + "AI 연결 정상" + 마지막 성공 시각(흐린 글). 불안정은 호박 점 + "AI 연결 불안정 마지막 성공 …". 저장소가 `local-fallback`이면 호박 배지 "데이터 저장소 대체 모드". 자세한 원인은 `title`로만 보여 준다. 외기온도는 항상 "지금 외기"로 시점을 밝히고, 재현 화면의 외기는 "재현 시각 외기 (날짜 시각)"로 적는다.
- **캐시 답변**: 코파일럿이 이전 답을 보여 줄 때는 답 위에 옅은 한 줄 안내(시각 포함)만 둔다. 백엔드가 덧붙인 인용문은 지워 중복을 없앤다.
- **일정 확인 패널**(일정·데이터, 코파일럿 초안 공통): 입력이 멈추고 0.6초 뒤 다시 확인하고, 확인이 끝나기 전에는 등록 버튼을 막는다. 겹침·정원 초과는 빨간 상자에 아이콘+문장으로, 문제가 없으면 초록 한 줄로 적는다. 대안 강의실은 추가 전력이 적은 순 목록(강의실, 유형·정원, 추가 kWh, "실외기 이미 가동" 배지, "이 강의실로 변경")이다. 문제가 남은 채 등록하려면 버튼이 위험 스타일 "문제를 알고 등록"으로 바뀐다.
- **공지 이미지 입력**: 글 입력 아래 같은 카드에 둔다. 실패 문구는 원인과 대안을 함께 적고, AI를 쓸 수 없을 때(429·503)는 "글로 입력하기" 버튼으로 글 입력란에 포커스를 옮긴다.
- **확인 결과의 세 가지 상태**: 겹침·정원 문제(빨간 상자, 문제 목록) / 문제는 없지만 `ok=false`(빨간 상자에 `note` 문장, 예: 그날 열리지 않는 강의) / 통과(초록 한 줄, 유형별 문장). 휴강·강의실 변경은 `target`을 "취소 대상 / 옮길 강의: 307호 10:00–13:00 지능형IoT플랫폼"으로 바로 아래에 적는다. 해석 결과에 `target`이 빠져 있으면 다시 확인해 채운다.
- **해석 실패 문구**: 422는 "일정으로 해석하지 못했습니다… 예: 27일 금 14~17시 405호 특강 40명"(이미지는 "공지 부분만 잘라 다시"), 429·503은 대안(글로 입력·직접 입력)을 함께 적는다. 캐시된 해석이면 출처 상자 안에 시각과 함께 한 줄로 알린다.

## 13. 깨지지 않는 화면

- 서버 응답은 모양을 확인한 뒤 쓴다(목록이 없으면 빈 목록, 필요한 숫자가 없으면 그 패널만 "값이 빠져 있습니다" 오류). 확인을 통과하지 못한 부분만 비우고 나머지 화면은 그대로 둔다.
- 마지막 방어선으로 `ErrorBoundary`를 화면(경로마다 따로, 이동하면 초기화), 코파일럿 패널, 앱 전체에 둔다. 대체 화면은 무엇이 안 됐는지, 어떻게 복구하는지(다시 시도·새로고침)와 오류 문장을 보여 주고, 사이드바와 상단 막대는 계속 동작한다.
- 이전 결과를 보여 주며 다시 계산 중인 응답(`stale`)에는 패널 머리에 "갱신 중"을 작게 표시하고 10초 뒤 다시 확인한다.
