# ThermoPlan 프런트엔드

부산대학교 IT관(3층 306·307·309·310, 4층 405–410) 시설 담당자를 위한 **스케줄 기반 냉난방 자동 운영 AI** 웹 화면입니다.
강의 시간표·이벤트·기상 예보로 만든 강의실별 운전 계획, 실행 검증, 4가지 운전 전략(고정·수동·규칙·AI) 비교를 한눈에 보여 줍니다.

## 실행

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173  (/api → http://localhost:8000 프록시)
npm run build      # 타입 검사(tsc -b) + 프로덕션 빌드 → dist/
npm run preview    # dist 미리보기 (같은 /api 프록시)
```

- 백엔드(FastAPI)가 `http://localhost:8000`에서 실행 중이어야 합니다. 모든 API 호출은 상대 경로 `/api/...`를 씁니다.
- 프로덕션 배포 시에는 `dist/`를 정적 호스팅하고 `/api`를 백엔드로 라우팅하면 됩니다(CloudFront 등).
- 화면은 1440×900(프로젝터 시연)과 1920×1080 기준으로 맞췄고, 1280px과 모바일(390px)에서도 깨지지 않습니다. 1536px 이상에서는 코파일럿 패널이 본문 옆에 붙고, 1024px 미만에서는 사이드바가 상단 가로 탭이 됩니다.
- 디자인 원칙과 토큰(색·글꼴·간격·차트·문구 규칙)은 [`DESIGN.md`](./DESIGN.md)에 있습니다. 새 화면을 만들 때 먼저 읽어 주세요.
- **v4 원칙: 단순하게, 누르면 자세히.** 화면마다 질문 하나에 답합니다. 첫 화면에는 답 한 문장 + 핵심 수치 최대 3개 + 주 시각물 하나만 두고, 나머지(보조 차트·표·설명·범례)는 펼침 목록, 팝오버(수치의 근거), 서랍(강의실 상세), 탭으로 한 번 눌러야 보입니다.

## 기술 스택

Vite 8 · React 19 · TypeScript(strict) · Tailwind CSS v4 · react-router-dom 7 · Apache ECharts 6(`echarts-for-react`) · lucide-react · react-markdown + remark-gfm · Pretendard Variable(npm `pretendard`, 동적 서브셋 자체 호스팅)

### 번들

화면마다 `React.lazy`로 나눠 첫 화면에는 공통 코드만 내려받습니다(`index` 약 304 kB, gzip 97 kB). ECharts(약 576 kB)는 차트가 있는 화면을 열 때, 코파일럿(마크다운 렌더러 포함, 약 184 kB)은 처음 열 때 불러옵니다. 펼침 목록 안의 차트와 요청(예: 강의실 재배치 권고)은 펼칠 때 처음 그리고 요청합니다.

## 색과 차트 규칙 (자세한 내용은 DESIGN.md)

- 크롬(내비·버튼·카드)은 옅은 바탕 `#f4f6f9`, 흰 카드(16px 모서리, 헤어라인 하나, 그림자 없음), 남색 잉크 `#142033`만 씁니다. 상호작용 색은 잉크 하나(주 버튼·선택 상태), 포커스 링만 파랑. 색은 데이터에만 씁니다.
- 온도는 발산형: 쾌적 범위(설정값, 기본 19.5–26.5℃) 안은 무채색, 아래로 갈수록 파랑, 위로 갈수록 주황.
- 운전 모드: 난방 `#dc5a2a` · 냉방 `#3f7fe0` · 송풍(외기 냉방) `#21a0a0`, 항상 아이콘과 글자를 함께 표시합니다.
- 기능별 절감 폭포: 합계는 전략 색, 규칙 단계는 파랑, AI 기능 단계는 청록, 전력이 늘어난 단계는 청록 테두리만(쾌적 비용). `cold_starts`는 춥거나 더운 시작을 모두 세므로 "시작 시 쾌적 이탈"이라고 부릅니다.
- 전략 색은 모든 화면에서 같습니다: 고정 `#565a60`(회색) · 수동 `#e09a00`(호박) · 규칙 `#2a78d6`(파랑) · AI `#14a673`(청록). 네 색 전체 쌍에 대해 색약 시뮬레이션(OKLab ΔE 8.8)과 정상 시각(ΔE 18.7) 검증을 통과했고, 범례와 직접 라벨을 함께 씁니다.
- 상태 색(정상 초록 · 자동 조치 호박 · 확인 필요 빨강)은 항상 아이콘+글자와 함께 표시합니다.
- 이중 y축을 쓰지 않습니다. 외기온도처럼 단위가 다른 값은 x축을 공유하는 아래 칸에 따로 그립니다.
- 주요 차트에는 `표로 보기` 버튼으로 같은 데이터를 표로 볼 수 있습니다.

## 오류에 강한 화면

- 서버 응답의 모양을 먼저 확인해 빠진 값은 그 패널만 오류로 보여 줍니다(`normCheck`, 기능별 절감 응답 검사 등).
- 화면별·코파일럿·앱 전체에 `ErrorBoundary`가 있어 예상 못 한 값이 와도 앱 전체가 빈 화면이 되지 않습니다.

## 접근성

- 모든 상호작용 요소에 키보드 포커스 링(`:focus-visible`, 2px)이 보입니다. 단면도의 강의실, 시간 막대(←/→ 5분, Shift 또는 PageUp/Down 1시간, Home/End), 검증 표의 행, 달력 칸도 키보드로 다룹니다. 상단 막대가 포커스된 요소를 가리지 않도록 `scroll-padding-top`을 둡니다.
- 서랍·모달·팝오버는 열릴 때 포커스를 옮기거나 버튼에 `aria-expanded`를 달고, Esc로 닫히며 원래 자리로 포커스를 돌려줍니다. 펼침 목록은 `aria-expanded`/`aria-controls`.
- 움직임은 150–250ms 투명도·위치만(높이 애니메이션 없음). `prefers-reduced-motion`이면 모두 끕니다.
- 글자 크기: 본문 14–17px, 보조 최소 13px(차트 축 눈금만 12px). 대비: 기본 16.4:1, 보조 7.4:1, 흐린 글 4.9:1.
