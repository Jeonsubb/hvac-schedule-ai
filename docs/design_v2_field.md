# 설계 v2: 현장 조사 반영 (2026-11-20)

## 현장 조사 요약 (부산대 시스템 에어컨 운영 사무실 인터뷰)

1. 정부 에너지 지침에 맞춰 운영자는 **온도 상·하한(Max–Min)만 설정**하고, 실내기는 그 범위 안에서 자율 조절한다.
2. 중앙 제어가 현재 **22 ℃ 고정**이다. 학생이 강의실에서 켜고 끄거나 온도를 바꿀 수 있지만 **약 1분 뒤 중앙 제어가 원래대로 되돌린다**.
3. 운영자는 제어 방식에는 불편이 없다고 했다. 대신 **문의·민원 응대가 부담**이고, AI가 답변·처리하고 정부 지침을 대신 설명해 주길 원한다.
4. 자동 운전 AI라면 **고정 22 ℃ 대신 AI가 범위 안에서 온도를 판단**해 주면 편하겠다는 의견이 있었다.
5. 공공기관이라 에너지 효율을 크게 신경 쓰지 않는 듯하다 → 별도 조사(`docs/research/field_policy_painpoints.md`).

## 전화 확인 (2026-11, 건물 관리자와 통화)

팀이 건물 관리자에게 직접 전화해서 운전 방식을 다시 확인했습니다.

1. 중앙에서는 정부 에너지 지침에 맞춘 **최대·최소 온도만 정해 두고**, 그 범위 안에서 **강의실 사람들이 자율로 켜고 끄고 온도를 맞춘다.**
2. **오후 6시가 되면 일괄로 차단하고, 그 뒤에는 다시 켤 수 없다.**

이 운영 방식은 채널PNU 2020-06-13 보도(강의실에서 자유롭게 켜고 끄며 18시에 일괄 차단)와도 일치합니다. 18시 이후에 다시 켤 수 없다는 점은 팀이 확인한 내용입니다.

### 비교 기준 "현재 운영"의 모델 (`hvac/strategies.py`의 `plan_fixed`)

| 항목 | 모델 | 근거 |
|---|---|---|
| 이름 | "고정 스케줄"에서 **"현재 운영"**으로 변경 | |
| 켜는 시각 | 강의실마다 그날 첫 수업이 시작할 때 재실자가 켠다(08:30 이전에는 켜지 않음) | 가정 |
| 끄는 시각 | 18:00에 중앙에서 일괄 차단. 그 전에는 아무도 끄지 않는다 | 차단 시각은 통화로 확인, "그 전에 끄지 않는다"는 가정 |
| 18:00 이후 | 재가동하지 않는다. 18:00 이후의 수업은 냉난방 없이 진행 | 팀 확인 |
| 수업이 없는 강의실 | 켜지 않는다 | 가정 |
| 설정온도 | 지침 범위의 끝(난방 최대 20℃, 냉방 최소 26℃) | 온도 숫자는 정부 지침 값을 넣은 가정 |

정책 기본값도 정부 지침에 맞춰 난방 18~20℃, 냉방 26~28℃로 두었습니다(이전에는 난방 최대 22℃).

### 새 기준의 학기 전체 시뮬레이션 (2026-11-21, 로컬 계산, 엔진 v15)

| 항목 | 현재 운영 | AI 예측 제어 |
|---|---|---|

| 전기요금 | 398,174원 | 327,310원 (약 7만 원, 17.8% 절감) |
| 수업 중 쾌적 시간 | 87.3% | 99.9% |
| 수업 시작 시 저온 | 367회 | 7회 |

- 주간 기준으로 현재 운영은 311.5시간을 켜 두고, 그중 수업은 187.5시간입니다. 나머지 124시간(40%)은 수업 사이와 수업이 끝난 뒤의 빈 강의실입니다.
- 주간 수업 237시간 중 49.5시간(강의 20개)이 18:00 이후라서 냉난방 없이 진행됩니다.
- 평일 75일 중 20일은 AI가 현재 운영보다 전력을 더 씁니다. 저녁 수업을 냉난방하고 아침에 예열하기 때문입니다.
- 절감률은 이전 기준들(08:30~22:30 전 강의실 가동 55.0%, 08:30~18:00 전 강의실 가동 37.3%)보다 낮습니다. 현재 운영이 이미 수업이 없는 강의실을 켜지 않기 때문입니다. 대신 차이는 쾌적에서 크게 납니다.

## 결정

| 영역 | 이전 | v2 |
|---|---|---|
| 비교 대상 | 고정·수동·규칙·AI 4개 | **현재 운영**(중앙 제어: 정해진 운전 시간 + 22 ℃ 고정, 재실자 조작은 1분 뒤 원복) vs **AI 자동 운전** 2개. 규칙 기반은 내부 분석(절감 요인)에만 사용 |
| 운영자 입력 | 설정온도 하나 | **정책 온도 범위**(난방 최소~최대, 냉방 최소~최대). 정부 지침·학교보건법 근거를 화면에 표시 |
| AI 설정온도 | 고정(20/26 ℃) | 수업마다 **체감 쾌적도(PMV, ISO 7730)가 중립에 가까운 가장 경제적인 온도**를 정책 범위 안에서 선택. 근거: 재실 인원(발열), 착의량(계절), 구조체 온도(복사), 실내 습도 |
| 쾌적 지표 | 실내온도가 19.5~26.5 ℃ 안인 시간 | 위 지표 유지 + **체감 쾌적 시간(|PMV| ≤ 0.5)**, 더움(PMV > +0.5)·추움(< −0.5) 시간 |
| 재실자 요청 | 없음 | 문의 AI가 범위 안 요청이면 해당 강의실·수업 동안 설정온도를 조정(`setpoint` 이벤트). 현재 운영은 1분 뒤 원복으로 모델링 |
| 문의 응대 | 없음 | **문의 응대 AI**: 학생·교직원 질문에 현재 상태 + 정책 지식베이스(출처 포함)로 답하고, 범위 안 조정은 자동 처리, 범위 밖·설비 고장은 운영자 확인 필요로 넘김. 운영자는 처리 내역만 본다 |
| 절감 요인 분해 | 고정 → 규칙 → 예측 → 날씨 → 재실 | 현재 운영 → 시간표 연동 → AI 설정온도 → 예측 기동·관성 정지 → 날씨 판단 → 재실 감지 |

## 가정 (화면에 "가정값"으로 표시, 설정에서 변경 가능)

- 현재 운영: 위 "전화 확인" 절의 모델을 따릅니다. 18:00 일괄 차단과 이후 재가동 불가는 확인한 내용이고, 켜는 시각(첫 수업 시작)과 설정온도 숫자는 가정값입니다. (처음에는 08:30~22:30 전 강의실 가동으로 가정했습니다.)
- 현재 운영 설정온도: 난방 20 ℃, 냉방 26 ℃(정부 지침 범위의 끝. 처음 인터뷰의 "22 ℃ 고정"은 전화 확인 내용으로 대체)
- 정책 범위 기본값: 조사 결과(`backend/seed/policy_kb.json`)에 맞춰 정함
- PMV 입력: 대사량 1.2 met(강의 수강), 기류 0.1 m/s, 평균복사온도 = 구조체 온도, 실내 습도 = 외기 수증기압 기준 추정

## 하지 않는 것

- 학생 개인 인증: 문의는 강의실 번호만 받는다(QR 링크 `?room=306`)
