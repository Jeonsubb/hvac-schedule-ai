# 설계 v2: 현장 조사 반영 (2026-11-20)

## 현장 조사 요약 (부산대 시스템 에어컨 운영 사무실 인터뷰)

1. 정부 에너지 지침에 맞춰 운영자는 **온도 상·하한(Max–Min)만 설정**하고, 실내기는 그 범위 안에서 자율 조절한다.
2. 중앙 제어가 현재 **22 ℃ 고정**이다. 학생이 강의실에서 켜고 끄거나 온도를 바꿀 수 있지만 **약 1분 뒤 중앙 제어가 원래대로 되돌린다**.
3. 운영자는 제어 방식에는 불편이 없다고 했다. 대신 **문의·민원 응대가 부담**이고, AI가 답변·처리하고 정부 지침을 대신 설명해 주길 원한다.
4. 자동 운전 AI라면 **고정 22 ℃ 대신 AI가 범위 안에서 온도를 판단**해 주면 편하겠다는 의견이 있었다.
5. 공공기관이라 에너지 효율을 크게 신경 쓰지 않는 듯하다 → 별도 조사(`docs/research/field_policy_painpoints.md`).

## 결정

| 영역 | 이전 | v2 |
|---|---|---|
| 비교 대상 | 고정·수동·규칙·AI 4개 | **현재 운영**(중앙 제어: 정해진 운전 시간 + 22 ℃ 고정, 재실자 조작은 1분 뒤 원복) vs **AI 자동 운전** 2개. 규칙 기반은 내부 분석(절감 요인)에만 사용 |
| 운영자 입력 | 설정온도 하나 | **정책 온도 범위**(난방 최소~최대, 냉방 최소~최대). 정부 지침·학교보건법 근거를 화면에 표시 |
| AI 설정온도 | 고정(20/26 ℃) | 수업마다 **체감 쾌적도(PMV, ISO 7730)가 중립에 가까운 가장 경제적인 온도**를 정책 범위 안에서 선택. 근거: 재실 인원(발열), 착의량(계절), 구조체 온도(복사), 실내 습도 |
| 쾌적 지표 | 실내온도가 19.5~26.5 ℃ 안인 시간 | 위 지표 유지 + **체감 쾌적 시간(|PMV| ≤ 0.5)**, 더움(PMV > +0.5)·추움(< −0.5) 시간 |
| 재실자 요청 | 없음 | 문의 AI가 범위 안 요청이면 해당 강의실·수업 동안 설정온도를 조정(`setpoint` 이벤트). 현재 운영은 1분 뒤 원복으로 모델링 |
| 문의 응대 | 없음 | **문의 응대 AI**: 학생·교직원 질문에 현재 상태 + 정책 지식베이스(출처 포함)로 답하고, 범위 안 조정은 자동 처리, 범위 밖·설비 고장은 운영자 확인 필요로 넘김. 운영자는 처리 내역만 본다 |
| 절감 요인 분해 | 고정 → 규칙 → 예측 → 날씨 → 재실 | 현재 운영 → 시간표 연동 → AI 설정온도 → 예측 기동·관성 정지 → 날씨 판단 → 재실 감지 |

## 가정 (화면에 "가정값"으로 표시, 설정에서 변경 가능)

- 현재 운영 운전 시간: 평일 08:30~22:30 (인터뷰에서 확인 못 함)
- 현재 운영 설정온도: 난방 22 ℃(인터뷰), 냉방 26 ℃(정부 권장)
- 정책 범위 기본값: 조사 결과(`backend/seed/policy_kb.json`)에 맞춰 정함
- PMV 입력: 대사량 1.2 met(강의 수강), 기류 0.1 m/s, 평균복사온도 = 구조체 온도, 실내 습도 = 외기 수증기압 기준 추정

## 하지 않는 것

- 실제 중앙 제어기 연동(BACnet): 계획 CSV 내보내기 유지
- 학생 개인 인증: 문의는 강의실 번호만 받는다(QR 링크 `?room=306`)
