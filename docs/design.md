# 설계 문서: 스케줄 기반 HVAC 자동 운전 AI (가칭 "ThermoPlan")

> 2026 AWS x PNU AI 해커톤 과제 3 · Cloud. 작성 2026-11-19. 발표 2026-11-21.

## 1. 문제와 고객

- **고객(주 사용자)**: 부산대 IT관의 시설 담당자(냉난방 운영자). 매일 아침 "오늘 어느 강의실을 언제 켜고 끌지"를 정하고, 시간표 변경(휴강·보강·행사)을 반영해야 한다.
- **현재 방식의 문제**: 건물 전체를 고정 시간(예: 평일 08:30~22:30)으로 가동하거나, 수업 시작 시각에 사람이 손으로 켠다. 고정 방식은 빈 강의실을 냉난방하고, 수동 방식은 수업 초반이 춥거나 덥고 끄는 것을 잊는다.
- **목표**: 시간표·이벤트·날씨를 합쳐서 강의실별 운전 계획을 자동으로 만들고, 실내기(IDU)·실외기(ODU) 시뮬레이터로 실행 이력을 남기고, 계획이 강의와 맞았는지 검증하고, 기존 방식 대비 에너지 절감과 쾌적도를 보여준다.

## 4. 운전 전략

같은 시뮬레이터에서 네 전략을 실행해 비교한다. 화면은 기본으로 "AI 최적화"를 실제 적용 전략으로 보여준다.

1. **고정 스케줄 (기준선 A)**: 평일 08:30~22:30 전 강의실 가동, 설정온도 고정.
2. **수동 운영 (기준선 B)**: 그날 첫 강의 시작 시각에 켜고, 마지막 강의 종료 30분 뒤에 끈다(끄는 것을 잊는 상황 반영). 선행 가동 없음.
3. **규칙 기반 (요구사항 ⑤)**: 세션마다 시작 10분 전 On, 종료 5분 전 Off, 공백 15분 이하는 유지.
4. **AI 최적화 (예측 제어)**: 열모델로 미래를 예측해서 아래를 결정한다.
   - **최적 기동**: 예보 외기온과 현재 실내 상태에서 몇 분 전에 켜야 시작 시각에 설정온도 ±0.5 ℃에 도달하는지 순방향 시뮬레이션으로 찾는다(0~60분, 5분 단위).
   - **가동 생략**: 냉난방 없이도 세션 동안 실내온도가 쾌적 범위에 머문다고 예측되면 송풍만 하거나 끈다.
   - **조기 정지(관성 활용)**: 종료 전에 꺼도 종료 시각까지 쾌적 범위를 유지하는 가장 이른 시각(최대 15분 전)에 끈다.
   - **공백 판단**: 세션 사이 공백마다 "유지"와 "껐다 다시 켜기"의 전력량을 시뮬레이션으로 비교해 적은 쪽을 고른다.
   - 설정온도: 난방 20 ℃, 냉방 26 ℃(공공기관 권장 기준 범위). 쾌적 범위: 19.5~26.5 ℃.
   - LLM은 이 수치 제어에 관여하지 않는다. 제어는 결정적 코드가 하고, LLM은 입력 해석·설명·질의응답을 맡는다.

## 5. 시뮬레이터 모델

- **열모델(2R2C, 강의실마다)**: 공기 노드 `Ta`와 구조체 노드 `Tm`.
  - `Ca·dTa/dt = (Tm−Ta)/Ram + (To−Ta)/Rao + Qint + Qsol + Qhvac`
  - `Cm·dTm/dt = (Ta−Tm)/Ram + (To−Tm)/Rmo`
  - 99 m² 기준 초기값: `Ca=1.5 MJ/K`, `Cm=20 MJ/K`, `1/Ram=1050 W/K`, `1/Rao=80 W/K`(창+침기), `1/Rmo=60 W/K`. 면적에 비례해서 조정. 1분 간격 오일러 적분(안정 조건 만족).
  - 내부발열: 재실자 75 W/인(현열), 조명 10 W/m², SW실습실 PC 100 W/대. 일사: 창 10 m² × SHGC 0.4 × 0.5 × 수평면 일사량.
  - 초기 상태: 학기 시작 7일 전부터 냉난방 없이 돌려서 워밍업한다.
- **IDU 제어**: 켜진 IDU는 이상적 온도조절기로 동작한다. 필요한 열량을 계산하고 용량으로 자른다. 난방 설정 이하이면 난방, 냉방 설정 이상이면 냉방, 그 사이면 송풍.
- **ODU 전력**: `P = Σ|Qhvac| / COP(To) × g(PLR) + 300 W(가동 시 기본) + IDU 팬 60 W/대`.
  - `COP_cool = 3.8 × clamp(1 + 0.03(35−To), 0.8, 1.6)`, `COP_heat = 3.4 × clamp(1 + 0.025(To−7), 0.55, 1.3)`
  - `g(PLR) = (0.12 + 0.7·PLR + 0.18·PLR²) / PLR` (PLR ≥ 0.1, 저부하 효율 저하 반영). PLR = ODU에 연결된 IDU 부하 합 / ODU 용량.
- **쾌적도**: 수업 중 실내온도가 쾌적 범위 안인 분의 비율, 시작 시각 실내온도, 불쾌 도·분(범위 밖 편차 × 분). ISO 7730 PMV(착의량은 계절별 0.5/1.0 clo, 대사량 1.1 met)도 계산한다.
- **현장 이상 상황 주입(정합성 검증용, 기본 켬, 시드 고정)**: 세션의 2%에서 수업 후 재실자가 IDU를 다시 켜고 떠남(수동 조작), 1%에서 On 명령이 실패함. 시스템은 이를 탐지해서 경고를 만들고, 빈 강의실 가동은 10분 뒤 자동으로 끈다.

## 6. 정합성 검증 규칙

세션마다 다음을 판정한다.
- **정상**: 시작 시각에 IDU가 켜져 있거나(또는 "가동 생략" 판정이 있고 실제 실내온도가 쾌적 범위), 수업 중 가동률 ≥ 95%.
- **불일치 유형**: `수업 중 꺼짐`, `선행 가동 부족(시작 시 쾌적 범위 밖)`, `빈 강의실 가동(세션 밖 가동이 계획 밖)`, `명령 실패`.
- 일별 일치율 = 정상 세션 / 전체 세션. 캘린더는 일치율과 절감률로 색칠한다.

## 8. 아키텍처 (AWS, ap-northeast-2)

```
브라우저 ─▶ CloudFront ─┬─ /*      ─▶ S3 (React 정적 파일, OAC)
                        └─ /api/*  ─▶ Lambda Function URL (FastAPI + Mangum, Python 3.13, arm64)
                                         ├─ DynamoDB (강의, 이벤트, 설정, 이력, 날씨, 변경기록)
                                         ├─ S3 (일별 시뮬레이션 결과 캐시, 업로드 파일)
                                         └─ Bedrock Runtime (Claude)
EventBridge Scheduler (매시) ─▶ 같은 Lambda (날씨 수집 → 오늘·내일 재계획 → 이력 기록)
```
- 기존 계정 리소스와 섞이지 않게 모든 리소스 이름에 `hvac-ai-` 접두사와 `project=hvac-ai` 태그를 붙인다.
- 배포는 CloudFormation 템플릿 하나와 배포 스크립트로 한다(CDK 부트스트랩 불필요).
- 기상청 키는 SSM Parameter Store(SecureString)에 저장하고 Lambda가 시작 시 읽는다. 저장소에 키를 넣지 않는다.

**계산과 캐시**: 엔진은 순수 Python이고 결정적이다. 하루(10개 강의실 × 4개 전략) 계산 결과를 `results/{설정해시}/{날짜}.json`으로 S3에 저장한다. 이벤트가 바뀌면 해당 날짜만 즉시 재계산하고, 설정이 바뀌면 학기 전체를 비동기로 재계산한다. 과거 날짜는 실측 날씨(Open-Meteo archive)로, 오늘과 미래는 기상청 예보로 계획한다. 계획에는 "예보", 시뮬레이션에는 "실측"을 쓴다(실측이 없으면 예보).

## 9. 화면 (시설 담당자 기준)

1. **운영 현황(홈)**: 현재 시각 기준 강의실 상태(3D 건물 뷰), 기상청 실황·예보, 오늘 타임라인(지금 선), 오늘 절감·쾌적 KPI, 경고, AI 브리핑.
2. **스케줄 캘린더**: 월간 캘린더(일치율·절감률), 날짜를 누르면 전체 강의실 간트(전략 전환, 실내온도 겹쳐보기).
3. **강의실 상세**: 주간 타임라인, 온도·전력 차트, IDU/ODU 이력 표.
4. **정합성 검증**: 일치율 KPI, 불일치 목록(유형별 필터), 강의실×날짜 히트맵.
5. **절감 효과**: 전략 비교(kWh·원·tCO2·쾌적도), 일별·누적 차트, 절감 요인 분해(워터폴), 강의실 재배치 제안.
6. **일정·이벤트**: 강의 DB 표, 가져오기(CSV/Excel/이미지/JSON), 자연어 이벤트 등록, 변경 기록(전후 비교).
7. **운영 규칙 설정**: 선행·조기정지·공백 분, 설정온도, 쾌적 범위, 기준선, 설비 구성(가정값).
8. **AI 코파일럿**: 모든 화면 오른쪽에서 여는 대화 패널.

## 10. 강의실 재배치 제안

요일마다 시간대별로 강의를 같은 유형(학부강의실/실습실/스튜디오)이고 정원이 충분한 강의실로 옮겨서 가동 ODU 수와 가동 강의실 수를 줄이는 탐욕 알고리즘을 쓴다. 제안마다 시뮬레이션으로 주간 절감 kWh를 계산하고, 상위 제안을 보여준다. 실제 반영은 이벤트(강의실 변경)로 등록한다.

## 11. 하지 않는 것

- 실제 설비 제어(BACnet 등) 연동: 시뮬레이터로 대체한다. 어댑터 경계만 둔다.
- 사용자 인증: 데모용. 대신 쓰기 API와 AI API에 요청 제한을 둔다.
- 교수 연구실 등 시간표 밖 공간: 데이터가 없어 이벤트 기능으로만 다룬다.

## Detailed Implementation Plan

1. `backend/hvac/` 엔진: `timetable.py`(CSV 파싱·블록 병합·세션 전개), `calendar.py`(학기·공휴일), `weather.py`(기상청·Open-Meteo 수집, 격자 변환), `model.py`(2R2C·VRF·PMV), `strategies.py`(4개 전략 계획), `simulate.py`(실행·이력·이상 주입), `validate.py`, `energy.py`(요금·탄소·요인 분해), `consolidate.py`.
2. `backend/app/`: FastAPI 라우터, 저장소 어댑터(로컬 JSON/S3·DynamoDB), Bedrock 클라이언트(추출·이벤트 파싱·코파일럿·브리핑).
3. `backend/tests/`: 세션 전개, 규칙(10분 전·15분 공백·조기정지), 열모델 에너지 보존 방향성, 정합성 판정, API 스모크 테스트.
4. `frontend/`: React + Vite + TypeScript + Tailwind + ECharts + react-three-fiber. 9장의 화면.
5. `infra/`: `template.yaml`(CloudFormation), `deploy.sh`(백엔드 패키징 → S3 업로드 → 스택 배포 → 프론트 빌드·동기화 → CloudFront 무효화 → 학기 사전 계산 실행).
6. 검증: 단위 테스트, 로컬 API 스모크, 배포 후 공개 URL에서 엔드포인트 점검과 헤드리스 브라우저 스크린샷 확인.

## 12. Goldfish 리뷰 반영 결정 (2026-11-20, Elephant 정리)

리뷰 원문: `docs/reviews/zoom_out.md`, `docs/reviews/design_critic.md`, `docs/reviews/implementation_readiness.md`. 사용자가 "묻지 말고 검증하면서 완성"을 요청했으므로, 승인 단계는 아래 결정으로 대신한다.

| 지적 | 결정 |
|---|---|
| 날짜 간 열 상태 연속성 vs 날짜별 캐시 (P0) | 날짜마다 독립 계산한다. 전날·전전날을 규칙 기반 계획과 실측 날씨로 워밍업한 상태에서 모든 전략이 **같은 초기 상태**로 하루를 시작한다. 공정 비교와 날짜 단위 재계산이 동시에 성립한다 |
| 정합성 95% 기준이 자기 계획을 실패로 판정 (P1) | 검증을 두 단계로 나눈다. ① 계획 검증: 모든 세션이 계획 구간 또는 근거 있는 생략 판정을 갖는가. ② 실행 검증: 계획된 On 분 중 실제 실행 비율 ≥ 95%, 시작 시 쾌적 범위, 수업 중 쾌적 ≥ 90%. 운영 전략(AI)만 검증한다. 이상 주입을 끈 날은 100%가 나와야 한다(테스트) |
| CloudFront 60초 한도, 스트리밍 불가 (P1) | 원본 타임아웃 60초. 코파일럿·이미지 추출·학기 재계산은 작업(job)으로 처리한다: DynamoDB에 작업 레코드 생성 → Lambda 비동기 자기 호출 → 브라우저 폴링. 코파일럿 진행 단계(도구 호출)를 레코드에 기록해서 화면에 실시간 표시한다 |
| 발표일이 토요일 (P1) | 전역 "기준 시각" 개념을 둔다. 오늘 강의가 없으면 가장 최근 강의일의 같은 시각을 기본값으로 쓰고, 화면 상단에 표시·변경할 수 있게 한다 |
| 환기 부하 없음 → 날씨 영향이 안 보임 (P1) | 재실 중 외기 도입 25 m³/h·인, 전열교환기 효율 60%를 열모델에 추가했다. 송풍(외기 냉방) 모드는 회수 없이 2배 도입. 고습(RH ≥ 75%, 외기 ≥ 22 ℃)이면 생략·외기 냉방을 금지하고 제습 운전 |
| AI가 규칙 대비 에너지 이득이 작음 (P1) | 정직하게 보여준다. 헤드라인은 기준선(고정·수동) 대비 절감, 규칙 대비는 "쾌적도 개선 + 생략·외기 냉방·재실 감지 정지로 인한 절감". 에너지-쾌적도 산점도를 주요 차트로 쓴다. 전략명은 "AI 예측 제어"로 하고 물리모델 기반임을 밝힌다 |
| "교수 부재 시 정지" 아이디어 누락 (P1) | 재실 감지 시나리오: 무단 휴강 3%, 조기 종료 8%(시드 고정, 모든 전략 동일). AI 운영은 재실 없음 10분 감지 후 자동 정지 |
| 생성형 AI가 주변 기능 (P1) | 핵심 루프: 코파일럿이 시간표·결과를 분석 → 운영 정책 제안 → 시뮬레이터로 검증(도구) → 운영자가 한 번에 적용 → 전후 비교. 숫자는 반드시 도구 결과에서만 인용하도록 지시한다. 일일 브리핑은 코파일럿에 통합 |
| 과거 날짜를 실측으로 계획(사후 지식) (P2) | 과거 날짜 계획은 Open-Meteo previous-runs의 **전날 발표 예보**, 실행은 실측(archive)을 쓴다. 오늘 이후는 기상청 단기예보(+3일) → Open-Meteo 예보(+15일) → 전년 동일 날짜(기후값) 순서. 일사량은 항상 Open-Meteo |
| 결과 파일 크기·캐시 키·이력 이중 저장 (P1/P2) | 날짜 결과는 5분 열 형식 JSON을 S3에 저장하고, 키에 입력 지문(세션·날씨·설정 해시)을 넣는다. 학기 요약 인덱스 파일을 따로 둔다. 기기 이력은 S3 날짜 파일에만 둔다. DynamoDB는 사용자 입력(강의·이벤트·설정·변경기록·작업·사용량)만 저장한다. 이벤트 변경 시 변경 전 요약을 변경기록에 스냅숏으로 남긴다 |
| 비용 통제 (P2) | CloudFront가 비밀 헤더를 붙이고 Lambda가 검사한다(Function URL 직접 호출 차단). LLM 호출은 DynamoDB 일일 카운터로 상한을 둔다. 계정 예산 경보(200달러)는 이미 있다 |
| Bedrock 세부 (P2) | Sonnet 5.5·Haiku 5.5는 강제 tool_choice와 기본값이 아닌 temperature를 거부한다. 구조화 출력과 낮은 effort를 쓴다. IAM은 global 프로필과 리전 없는 모델 ARN을 모두 허용한다. 배포 후 모델별 스모크 테스트 |
| 범위 과다, 컷라인 없음 (P0/P1) | 3D → SVG 평면도, 화면 6개로 축소(운영 현황 / 스케줄·타임라인 / 정합성 / 절감 효과 / 일정·데이터 / 설정), 코파일럿은 공통 패널. 순서: 엔진+테스트 → API → 배포 골격 → 화면 → AI 기능 → 다듬기 |
| 실제 설비 연동 질문 (P3) | 계획을 중앙제어기용 CSV(기기, 시각, On/Off, 설정온도)로 내보내는 기능 제공. 재배치는 학사 부서용 "권고 보고서"로 표현 |
| 시험 기간 (P3) | 데이터상 시간표대로 진행한다고 가정하고 화면에 명시 |
