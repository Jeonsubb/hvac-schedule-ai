## 촬영 전 준비

1. `AWS_PROFILE=hvac ./infra/deploy.sh demo-reset`으로 초기화하고, 시크릿 창에서 새 계정으로 시작합니다.
2. `gateway/run_demo.sh start`를 실행하고, 연결 테스트 결과에 "실제 게이트웨이에서 BACnet으로 읽은 값입니다."가 표시되는지 먼저 확인합니다. 촬영 뒤에는 `gateway/run_demo.sh stop`으로 끕니다.
3. 토요일에는 수업이 없으므로 기준 날짜를 11/20(금)으로 맞춥니다. 휴강의 효과가 드러나려면 기준 시각이 수업 시작 전이어야 합니다.
4. 음성 문장을 조용한 곳에서 두세 번 시험하고 마이크 권한을 미리 허용합니다. 과목명 인식이 불안정하면 "오늘 307호 10시 수업 휴강"처럼 강의실과 시각으로 말합니다. 화면 녹화에 시스템 소리와 마이크가 함께 들어가도록 설정합니다.
5. AI 협의는 1분 안팎이 걸리므로 중간을 배속으로 편집합니다. "규칙 기반 대체 실행 (Bedrock 응답 아님)" 배지가 붙으면 다시 촬영합니다.
6. 휴강과 특강을 등록하면 데이터가 바뀌므로, 다시 촬영할 때는 초기화부터 반복합니다.

## 사실대로 말해야 하는 부분

- 확인한 내용: 중앙에서는 정부 에너지 지침의 최대·최소 온도만 정하고 강의실에서 자율로 켜고 끈다, 오후 6시에 일괄 차단하고 그 뒤에는 다시 켤 수 없다(채널PNU 2020-06-13 보도와 일치).
- 가정: "첫 수업이 시작할 때 켠다", "6시 전에는 아무도 끄지 않는다", 설정온도 숫자(난방 20℃, 냉방 26℃). 이 부분은 들은 것처럼 말하지 않고 "시간표와 겹쳐 계산해 보면"이라고 말합니다.
- 13.5%, 87.3%, 367회, 40%, 49.5시간은 2026-11-21에 로컬에서 새 기준으로 계산한 값(엔진 v15)입니다. 배포본이 새 기준인지 촬영 전에 절감 효과 화면의 "현재 운영" 값으로 확인합니다.
- 전력 절감률은 13.5%로 크지 않습니다. 현재 운영이 이미 수업 없는 강의실을 켜지 않기 때문입니다. 절감률만 내세우지 말고 쾌적과 저녁 수업을 함께 말합니다. 평일 75일 중 20일은 AI가 전력을 더 씁니다(저녁 수업 냉난방과 아침 예열).
- 시연 날짜 11/20은 현재 운영 49.6 kWh·쾌적 81.8%, AI 37.8 kWh·쾌적 100%입니다.
- 연결 대상은 실제 부산대 중앙제어기가 아니라, 같은 BACnet/IP 규약으로 응답하는 가상 중앙제어기입니다.
- 절감 수치, 실내온도, CO₂는 모두 시뮬레이션 결과입니다.
- 백엔드는 IT관 하나만 계산하므로, 가입할 때 기관은 부산대학교, 건물은 IT관으로 입력해야 화면과 설명이 일치합니다. 여러 건물을 이미 운영한다고 말하지 않습니다.
- 가입과 로그인은 목업입니다. 이메일의 실제 수신과 음성의 전체 경로는 촬영 전에 직접 확인한 범위까지만 보여 줍니다.

# 데모 시나리오 v6 (4분) — 타임라인 메인 + AI 협의 전후 비교

> 이전 대본입니다(2026-11-21 새벽 기준). 최신 동선은 맨 위의 v7입니다. 아래쪽 "데모 시나리오 (3~4분)"는 그보다 앞선 화면 구성(v5) 기준의 기록입니다.

발표일(토)은 수업이 없으므로, 상단의 기준 날짜를 **수업이 있는 평일**(예: 11/19 목, 11/20 금)로 맞추고 시작합니다.

주의할 점
- 결과가 "쾌적성 조건 우선으로 예상 소비량 증가"로 나올 수 있습니다. 화면은 실제 계산 결과를 그대로 보여 주므로 trade-off로 설명합니다.
- Bedrock이 실패하면 "규칙 기반 대체 실행 (Bedrock 응답 아님)" 배지가 붙습니다. 이 경우 다시 실행하거나, 미리 실행해 둔 날짜의 "이전 실행 기록"을 보여 줍니다.

## 예상 질문

- **고정 스케줄은 허수아비 기준 아닌가?** 그래서 같은 쾌적도 비교(규칙 30분 전 대비 −12.0%)와 수동 운영 대비(−21.0%)를 함께 보여줍니다.
- **AI가 왜 규칙보다 나은가?** 워터폴이 답입니다. 예측 기동은 오히려 전력을 조금 더 쓰지만 수업 시작 쾌적 이탈을 152회에서 6회로 줄이고, 날씨 판단과 재실 감지가 그보다 많이 줄입니다.
- **재실 감지는 진짜인가?** 강의실 재실 센서(PIR·CO₂) 또는 출결 시스템 연동을 가정한 시뮬레이션입니다. 기여는 학기 −51 kWh로 가장 작은 단계입니다.
- **수치를 믿을 수 있나?** 설비 물리값은 가정값입니다. 같은 모델·같은 날씨·같은 현장 상황에서 기능을 하나씩 켜는 상대 비교로 보여줍니다. 실외기 곡선은 EnergyPlus VRF 예제 형태, 요금은 한전 교육용(을) 공식 요금표입니다.
- **실제 설비 연동은?** 계획을 중앙제어기용 CSV(기기, 시각, On/Off, 설정온도)로 내보냅니다.
- **AWS 구성은?** 전부 서버리스입니다. 웹은 CloudFront+S3, API는 Lambda(Function URL), 데이터는 DynamoDB+S3, AI는 Bedrock이고, 매시 날씨 갱신은 EventBridge Scheduler가 Lambda를 부릅니다. 오래 걸리는 AI 작업(시간표 추출, 코파일럿)은 Lambda가 자기 자신을 비동기로 호출해서 처리하고, 실행 역할마다 필요한 권한만 붙였습니다.
- **이미지 추출은 믿을 만한가?** CSV로 그린 시간표 이미지 2장에서 42/42 블록이 일치했고, 실제 휴강 공지 형식 캡처도 처리합니다. 실제 사진 정확도는 추가 검증이 필요합니다.
