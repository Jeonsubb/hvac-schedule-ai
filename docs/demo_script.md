4. 상단 표시줄이 "AI 연결 정상"인지 확인

## 0. 문제와 고객 (20초)

- "IT관 10개 강의실 냉난방을 평일 08:30~22:30 고정으로 켜 두면, 실제 강의가 있는 시간은 그중 34%(주 237시간/700시간)뿐입니다."
- 고객은 시설 담당자입니다. 매일 시간표·휴강·행사를 반영해서 어느 방을 언제 켜고 끌지 정해야 합니다.

## 1. 운영 현황 (40초) — 요구사항 ②

- 건물 단면도: 10:40 현재 수업 중인 307·410호만 난방 중(바닥 색 = 실내온도, 앞면 = 운전 모드), 실외기 3대 중 2대 가동.
- "오늘 최저 −0.3℃. AI는 강의실마다 예측 실내온도와 실외기 분담 출력으로 18~39분 전에 예열을 시작했습니다. 실내기가 1대뿐인 410호가 39분으로 가장 깁니다."
- 시간 막대를 재생해서 하루 운전을 1분 단위로 보여줍니다.
- 규칙 기반 대비 칸: 오늘 AI가 약 2.9 kWh 더 썼지만, 수업 시작 때 쾌적 범위를 벗어난 강의가 **규칙 4/5 → AI 0/5**입니다. 더 쓴 전력은 수업 전에 미리 데운 몫입니다.

## 2. 스케줄·타임라인 (40초) — 요구사항 ③⑤

- 캘린더에서 11/20 → 10개 강의실 간트: 강의 블록 아래에 계획과 실제 가동이 겹쳐 보입니다.
- 전략을 "규칙 기반"으로 바꾸면 10분 전 On, 5분 전 Off, 15분 이내 연속 유지가 그대로 보입니다.
- 410호를 열어 실내온도 곡선: 10:00 수업 시작 시점에 **수동 11.4℃, 규칙(10분 전) 15.8℃, AI 20.0℃**.

## 3. 일정 변경 → 즉시 재계산 (50초) — 요구사항 ①⑤, 생성형 AI

- 자연어 입력: "다음 주 수요일 405호 18~21시 캡스톤 특강 50명" → Claude(Haiku 5.5)가 이벤트 초안으로 변환합니다.
- 결정적 충돌 검사: **405호 16:30~18:30 공학작문및발표와 겹침** → 추가 전력이 가장 적은 빈 강의실 **307호(+0.37 kWh, 3층 실외기가 이미 가동 중)** 추천 → 클릭 한 번으로 변경 → 등록 → 전후 비교 카드.
- 휴강 공지 캡처 업로드("예시 휴강 공지로 해 보기"): **11/27(금) 307호 지능형IoT플랫폼 휴강**을 2~3초 만에 읽어 휴강 이벤트로 만듭니다. "교수님이 안 계시면 냉난방도 꺼진다"를 그대로 보여주는 장면입니다.

## 4. 정합성 검증 (25초) — 요구사항 ③

- 계획 검증(모든 강의에 계획 또는 근거 있는 생략)과 실행 검증(계획 대비 실행, 시작 시 쾌적, 수업 중 쾌적)을 따로 봅니다.
- 자동 조치 사례: 무단 휴강(재실 없음 10분 → 정지, 다음 수업 30분 전 재가동), 수업 후 수동 가동(빈 강의실 감지 → 정지), 명령 실패(재전송), 예보 오차(피드백 보정).

## 5. 절감 효과 (45초) — 요구사항 ④⑥

범위를 **학기 전체**로 놓고 설명합니다.
- 맨 위 문장: **같은 쾌적도라면** 규칙 기반은 30분 전에 켜야 해서 3,254 kWh(시작 시 쾌적 이탈 16회), AI는 2,864 kWh(7회)로 **12.0% 적게** 씁니다.
- 워터폴 "AI 절감은 어디서 오는가": 고정 스케줄 → 수업 시간에만 운전 −3,372 kWh(시작 이탈 152회) → **예측 기동·관성 정지 +91 kWh(쾌적을 위한 전력, 이탈 152→6회)** → 날씨 판단 −170 kWh → 재실 감지 −51 kWh = AI.
- 고정 스케줄 대비 55.0% 절감, 전기요금 749,938원 → 326,416원, CO₂ 1.46 t 감축.
- 강의실 재배치 권고(학사 부서 검토용): 금요일 3개 강의를 옮기면 실외기 가동 16.2h → 9.5h, 학기 금요일 전력 19.5% 절감.

## 6. AI 코파일럿 (30초)

- 질문: "선행 가동을 10분에서 5분으로 줄이면 이번 주 에너지와 쾌적도가 어떻게 바뀌는지 시뮬레이션해줘"
- 화면에 규칙 시뮬레이션 도구 호출 단계가 보이고, 결과를 근거로 "규칙 기반 전력은 조금 줄지만 시작 시 쾌적 이탈과 불쾌 지표가 늘고, AI 전략은 영향이 없음 → 적용하지 않음"이라고 답합니다(수치는 모두 도구 결과).
- 메시지: 수치 제어는 검증 가능한 엔진이, 해석·입력·설명은 생성형 AI가 맡습니다. LLM이 HVAC를 직접 제어해서 지속 운영한 사례는 없다는 2026년 리뷰(66편)와 같은 결론입니다.

## 예상 질문

- **고정 스케줄은 허수아비 기준 아닌가?** 그래서 같은 쾌적도 비교(규칙 30분 전 대비 −12.0%)와 수동 운영 대비(−21.0%)를 함께 보여줍니다.
- **AI가 왜 규칙보다 나은가?** 워터폴이 답입니다. 예측 기동은 오히려 전력을 조금 더 쓰지만 수업 시작 쾌적 이탈을 152회에서 6회로 줄이고, 날씨 판단과 재실 감지가 그보다 많이 줄입니다.
- **재실 감지는 진짜인가?** 강의실 재실 센서(PIR·CO₂) 또는 출결 시스템 연동을 가정한 시뮬레이션입니다. 기여는 학기 −51 kWh로 가장 작은 단계입니다.
- **수치를 믿을 수 있나?** 설비 물리값은 가정값입니다. 같은 모델·같은 날씨·같은 현장 상황에서 기능을 하나씩 켜는 상대 비교로 보여줍니다. 실외기 곡선은 EnergyPlus VRF 예제 형태, 요금은 한전 교육용(을) 공식 요금표입니다.
- **실제 설비 연동은?** 계획을 중앙제어기용 CSV(기기, 시각, On/Off, 설정온도)로 내보냅니다.
- **AWS 구성은?** 웹은 CloudFront+S3, 데이터는 DynamoDB+S3, AI는 Bedrock입니다. 배포 계정에 IAM 역할 생성 권한이 없어서 API는 EC2에서 돌고, 역할만 생기면 Lambda로 바꾸는 템플릿이 준비되어 있습니다(이슈 #1).
- **이미지 추출은 믿을 만한가?** CSV로 그린 시간표 이미지 2장에서 42/42 블록이 일치했고, 실제 휴강 공지 형식 캡처도 처리합니다. 실제 사진 정확도는 추가 검증이 필요합니다.
